# Web 可扩展性

## 阅读推荐

1. web scalability for startup engineers, Artur Ejsmont
2. System Design 1 & 2, Alex Xu

## What Is Scalability? 什么是可扩展性?

+ 处理更多数据
+ 处理更高的并发
+ 处理更高频次的交互
+ 合理的性能和成本

## 单体服务器

单服务器是最简单的配置,这也是许多小型项目的起点。
用户连接到DNS以获取托管网站的服务器的IP地址。一旦获得IP地址,他们就直接向你的Web服务器发送HTTP请求。
任何网页、图像、CSS文件和视频都必须由服务器生成或提供,所有流量和处理都必须由单台机器处理。

小型网站甚至可能不需要专用服务器,通常可以托管在虚拟专用服务器(VPS)或共享主机上。

### 单体服务器为什么不行？

原因很多：
+ 用户群增长,从而增加流量。
+ 每个用户都会给服务器增加额外的负载,为每个用户提供服务会消耗更多的资源,包括内存、CPU时间和磁盘I/O。
+ 用户增长，带来更多数据,数据库会增长。当这种情况发生时,由于额外的CPU、内存和I/O需求,数据库查询开始变慢。
+ 用户更多的需求，添加新功能来扩展系统,这使得用户交互需要更多的系统资源。

## 垂直扩展

应用程序达到服务器的极限(由于流量增加、处理的数据量或并发级别)。有两种不同类型的扩展:垂直和水平。
垂直可伸缩性：通过升级硬件和/或网络吞吐量来实现。

短期最简单解决方案,不需要对应用程序进行架构更改：
+ 在RAID阵列中添加更多硬盘来增加I/O容量
+ 切换到固态硬盘(SSD)来改善I/O访问时间
+ 增加RAM来减少I/O操作
+ 升级网络接口或安装额外的网络接口来提高网络吞吐量
+ 切换到具有更多处理器或更多虚拟内核的服务器

### 垂直扩展的限制

1. 成本
2. 硬件上限

Expensify的案例中，工程师比较了AWS EC2 x1e.32xlarge，一年23.3W，且性能只能达到每秒钟1.5M, 最后他们自己买了一个设备放在自己的机房里。

## Isolation of Services 服务隔离

一个简单的解决方案是将系统的不同部分移动到单独的物理服务器上,在单独的物理机器上安装每种类型的服务。
服务是一个应用程序,如Web服务器(例如Apache)或数据库引擎(例如MySQL)。Web服务器和数据库提供了单独的专用机器。以同样的方式,你可以部署其他服务,如FTP、DNS、缓存等,每个服务都在专用的物理机器上。

CDN: 内容分发网络是一种托管服务,负责静态文件(如图像、JavaScript、CSS和视频)的全球分发。客户端连接到CDN提供商拥有的服务器。
如果CDN服务器还没有请求的内容,它会向你的服务器请求并缓存。一旦文件被CDN缓存,后续客户端将在不与服务器联系的情况下得到服务。

## 水平扩展

真正水平可伸缩的系统不需要强大的服务器
通常运行在大量廉价的"商用"服务器上,而不是少数强大的机器上

+ 单位成本更低（对比垂直扩展）
+ 没有硬件限制

### stateless 无状态服务

服务层的scaling方式需要将所有 Web 服务无状态化：将所有共享状态从 Web 服务转移到共享数据存储,如对象缓存、数据库和消息队列。

1. 可以在 Web 服务和客户端之间部署负载均衡器,每个请求都可以发送到任何可用的 Web 服务机器。允许更好的负载分配和更大的灵活性。
2. 由于每个 Web 服务请求都可以由任何一台 Web 服务机器提供服务,因此一旦机器崩溃,你就可以将服务机器从负载均衡器池中取出。大多数现代负载均衡器都支持心跳检查,以确保为流量提供服务的 Web 服务机器可用。一旦机器崩溃或遇到其他类型的故障,负载均衡器将从负载均衡池中删除该主机,从而减少集群的容量,但防止客户端超时或无法获得响应。
3. 通过使 Web 服务机器无状态,可以随时重新启动和停用服务器,而不必担心会影响客户端。例如,如果你想关闭服务器进行维护,你需要将该机器从负载均衡器池中移除。大多数负载均衡器都支持主机的优雅移除,因此不再将来自客户端的新连接发送到该服务器,但不会终止现有连接以防止客户端错误。从池中删除主机后,你需要等待所有打开的连接被客户端关闭,这可能需要一两分钟,然后你可以安全地关闭机器而不会影响任何单个 Web 服务请求。
4. 类似于停用,你将能够执行 Web 服务的零停机更新。你可以通过将一台服务器从轮换中取出、升级,然后将其重新放入轮换中,一次部署一台服务器更新。如果你不想同时运行两个不同的版本,可以部署到备用堆栈并在负载均衡器级别一次性切换所有流量。无论你选择哪种方式,无状态 Web 服务都意味着易于维护。
5. 通过从 Web 服务中删除所有应用程序状态,你将能够通过简单地添加更多克隆来扩展 Web 服务层。你需要做的就是向负载均衡器池添加更多机器,以便能够支持更多并发连接、执行更多网络 I/O 以及计算更多响应(CPU 时间)。
6. 如果你使用支持自动扩展负载均衡器(如 Amazon Elastic Load Balancer 或 Azure Load Balancer)的云托管服务,你可以以与前端相同的方式实现 Web 服务集群的自动扩展。
