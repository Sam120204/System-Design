# Web 应用前端架构：状态管理与扩展组件

## HTTP Session

以未登录的匿名身份把商品加入 Amazon 购物车时，服务端通常会创建或关联一个匿名会话。浏览器通过 Cookie 携带会话标识（如 `session id`）；购物车内容保存在服务器或后端存储中，并与该会话标识关联一段时间。因此，只要浏览器仍携带同一套 Cookie，刷新页面或隔天再访问时，通常还能看到之前的购物车。

- **HTTP 协议本身是无状态的**：每个请求彼此独立。
- **应用层可以有状态**：购物车等用户状态保存在后端，Cookie 中的会话标识把请求与相应状态关联起来。
- **计算层可以设计为无状态**：任一服务实例都能处理请求；购物车、库存等状态由数据层保存。这样，请求即使被负载均衡到不同机器，也能访问同一份状态。

## 会话状态

会话状态的处理方式包括：

1. 在 Cookie 中存储会话状态。
2. 将会话存储委托给外部数据存储。
3. 使用支持粘性会话的负载均衡器。

## 文件存储

Web 应用程序前端服务器的第二个最常见的状态类型是文件存储，需要区分两种情况：

- 用户生成的内容被上传到服务器。
- 系统生成的文件需要由用户下载。

## 可扩展前端的组件

- DNS
- CDN
- Cache（缓存）
- Load Balancer（负载均衡器）

### 负载均衡器

负载均衡器有助于实现以下目标：

- **隐藏后端服务器**：由负载均衡器提供统一入口，客户端无需直接访问各个服务实例。
- **无缝增加容量**：新增实例后，可以把请求分配给它们。
- **高效管理故障**：把请求从故障实例转移到健康实例。
- **支持自动扩展**：配合自动扩展机制，将流量分配给新增或缩减后的实例。
- **有效管理资源**：在多个实例之间分配流量，提高资源利用率。
